# Алтын мерейтой

Персональное приглашение на 50-летие Нұрман Нұғманұлы. Казахский интерфейс, React + Vite, собственные CSS-анимации, без фотографий и неизвестных сведений. Дата: 5 декабря 2026, 18:00, UTC+5.

## Запуск

Нужен Node.js 22.12+ или 24 и npm.

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173). В PowerShell при запрете выполнения npm.ps1 используйте `npm.cmd` вместо `npm`.

```bash
npm test
npm run build
npm run preview
```

Готовые файлы находятся в `dist/`. Шрифты Cormorant Garamond и Noto Sans загружаются через Google Fonts с поддержкой кириллицы; при отсутствии сети используются Georgia и системный sans-serif. Для полностью автономного размещения скачайте лицензированные WOFF2 с казахскими символами и замените импорт в `src/styles.css` локальными `@font-face`.

## Структура

- `src/main.jsx` — компоненты конверта, письма, юбиляра, даты, формы и благодарности.
- `src/components/InvitationIntro.jsx` и `invitation-intro.css` — отдельная сцена открытия чёрного конверта с двусторонним 3D-клапаном, печатью «50» и увеличением письма до размеров настоящего приглашения.
- `src/styles.css` — адаптивный дизайн, орнамент, анимации и reduced motion.
- `src/config/forms.js` — единственная конфигурация подключения формы.
- `src/lib/submitRsvp.js` — отправка и разделение подтверждённого/неподтверждённого результата.
- `src/config/event.js` — точное время начала (`2026-12-05T18:00:00+05:00`, Asia/Oral), адрес Symbat и ссылка 2ГИС.
- `src/components/EventDetails.jsx` и `event-details.css` — место проведения и живой отсчёт перед RSVP; `src/lib/countdown.js` — расчёт по абсолютному времени без зависимости от часового пояса гостя.
- `tests/rsvp.test.js` — проверки честного поведения отправки.
- `.github/workflows/deploy.yml` — сборка и публикация GitHub Pages.

## Подключение Google Forms

Подключена [опубликованная форма](https://docs.google.com/forms/d/e/1FAIpQLSfiNwo6R9rjkjwOea71OK2XyuDItfZkrpTBKTeepXy9RAhqrw/viewform), режим `mode: 'google'`. Настройки в `src/config/forms.js`:

| Поле сайта | Название в Google Forms | Entry ID |
| --- | --- | --- |
| Аты-жөніңіз | Аты-жөніңі: | `entry.999691961` |
| Мерейтойға қатысасыз ба? | Мерейтойға қатысасыз ба? | `entry.944653112` |
| Ізгі тілегіңіз | Ізгі тілегіңіз | `entry.1155546494` |

Имя и участие обязательны, пожелание необязательно. Реальные варианты участия: `Қатысамын`, `Қатыса алмаймын`. В опубликованной Google Form пожелание имеет тип короткого текста; сайт сохраняет своё существующее текстовое поле. Реальные тестовые ответы при подключении не отправлялись.

POST идёт на тот же публичный URL с окончанием `/formResponse`, тело — `URLSearchParams` с тремя entry ID. API-ключи, cookies и сервер на GitHub Pages не требуются. Пустые или некорректные настройки включают демонстрационный режим. Для явного отключения отправки установите `mode: 'demo'`.

При замене формы:

1. Создайте Google Form с обязательным коротким ответом «Аты-жөніңіз», обязательным одиночным выбором «Мерейтойға қатысасыз ба?» (точные варианты: «Қатысамын», «Қатыса алмаймын») и необязательным абзацем «Ізгі тілегіңіз».
2. Разрешите ответы без входа в Google. Не включайте ограничение одного ответа, требующее авторизации. Опубликуйте форму и откройте приём ответов.
3. В меню Google Forms получите предварительно заполненную ссылку. Заполните поля различимыми значениями. Из URL скопируйте идентификаторы `entry.…` для каждого поля и публичный ID формы из `/d/e/…/viewform`.
4. В `src/config/forms.js` установите `mode: 'google'`, реальный `googleFormUrl`, заканчивающийся `/formResponse`, и три реальных `entries`. Пустые или некорректные настройки сохраняют демонстрационный режим.
5. Пересоберите проект. Тестовый ответ отправляйте только с разрешения владельца.

Прямая отправка использует `no-cors`: Google не предоставляет странице доступ к результату. Поэтому сайт честно сообщает, что сохранение не подтверждено. Даже успешно завершившийся `fetch` не запускает благодарность. Не заменяйте это искусственным успехом или проверкой загрузки скрытого iframe.

### Подтверждённая отправка и экран благодарности

Для настоящей благодарности настройте отдельный HTTPS endpoint (например, собственную serverless-функцию), который сохраняет ответы в Google Forms и возвращает подтверждение. GitHub Pages сам серверный код не исполняет.

Установите `mode: 'verified'` и реальный `verifiedEndpoint`; Google entry ID в этом режиме использует сервер. Endpoint принимает POST JSON:

```json
{"name":"…","attendance":"Қатысамын","wish":"…"}
```

Он должен проверять длины и обязательность полей, точные варианты участия, ограничивать частоту запросов и возвращать HTTP 200 с `{"ok":true}` **только после подтверждённого сохранения**. При ошибке верните 4xx/5xx либо `{"ok":false}`. Поддержите CORS OPTIONS/POST для домена приглашения и заголовка Content-Type; секреты держите только на сервере. Для Google Apps Script используйте серверный `FormApp` и `FormResponse.submit()`, но заранее проверьте возможность чтения ответа браузером: один `doPost` без подходящего CORS не решает эту задачу. Не используйте JSONP для передачи персональных данных через URL.

Только читаемый успешный ответ с `ok: true` открывает «Рақмет! Жауабыңыз қабылданды.». При сетевой ошибке или тайм-ауте текст остаётся в форме; автоматических повторов нет, поскольку сервер мог уже сохранить ответ.

Подробная альтернатива через Google Apps Script и CORS-прокси, без встраивания стандартной формы: [docs/apps-script.md](docs/apps-script.md).

### Как владельцу проверить тестовый ответ

1. Откройте форму **в редакторе под своей учётной записью**, вкладку «Ответы». Публичная ссылка `/viewform` не предоставляет доступ к полученным ответам. Убедитесь, что приём ответов включён и для гостя не требуется вход в Google.
2. После собственного решения выполнить проверку откройте сайт, введите узнаваемое имя, например `ТЕСТ — удалить`, выберите вариант участия и нажмите отправку **один раз**. Для второго варианта участия сделайте отдельный тест только при необходимости. Сайт сообщит, что сохранение не подтверждено; это ожидаемо при прямой отправке.
3. В редакторе Google Forms откройте «Ответы» → «Отдельный пользователь» и найдите имя, время, участие и пожелание. Именно наличие записи подтверждает сохранение, а не статус запроса в браузере.
4. Для Google Sheets во вкладке «Ответы» нажмите зелёный значок таблицы / «Связать с Таблицами», выберите новую или существующую таблицу. Откройте её и найдите строку с тем же именем, временной меткой и значениями трёх полей. Таблица может обновиться с небольшой задержкой.
5. Если записи нет, проверьте доступ без авторизации, приём ответов, неизменность вопросов/entry ID и точное совпадение вариантов участия. Не повторяйте отправку автоматически: первый ответ мог сохраниться с задержкой.
6. При удалении теста проверьте и Google Forms, и связанную Google Sheets: удаление ответа в форме не гарантирует удаления строки из таблицы.

## Бесплатная публикация на GitHub Pages

1. Создайте пустой публичный репозиторий **toi-invitation** на GitHub, без автоматически создаваемых README, .gitignore и лицензии. Локальный Git-репозиторий уже подготовлен в папке `toi`; `package-lock.json` включён в исходники, а `node_modules`, `dist`, `.env` и временные файлы исключены.
2. В Settings → Pages → Build and deployment выберите **GitHub Actions**.
3. Запустите workflow вручную во вкладке Actions или отправьте коммит в `main`.
4. После завершения откройте адрес из deployment в Actions / Settings → Pages.

В `vite.config.js` задан `base: '/toi-invitation/'`. После публикации адрес будет `https://YOUR_USERNAME.github.io/toi-invitation/`. При смене имени репозитория обновите `base`. Реальные ID формы публичны по природе; пароли, ключи и сервисные учётные данные в клиентский проект не добавляйте. Дизайн, дата, конверт, таймер, Symbat, 2ГИС и существующее подключение Google Forms сохранены.

Команды для привязки (замените `YOUR_USERNAME` на имя своей учётной записи GitHub):

```powershell
cd "C:\Users\nurma\OneDrive\Рабочий стол\toi"
git remote add origin https://github.com/YOUR_USERNAME/toi-invitation.git
git remote -v
```

Если `origin` уже существует, вместо `remote add` используйте `git remote set-url origin https://github.com/YOUR_USERNAME/toi-invitation.git`.

**Только после вашего подтверждения публикации** выполните:

```powershell
git push -u origin main
```

Автоматическая публикация запускается после этого push. В репозитории выберите **Settings → Pages → Build and deployment → Source: GitHub Actions**. Workflow уже существует — создавать предложенный GitHub шаблон не нужно. Во вкладке **Actions** дождитесь успешного workflow **Deploy invitation to GitHub Pages**, затем откройте ссылку из задания `deploy` либо **Settings → Pages → Visit site**. Если push произошёл до выбора Source, после настройки запустите workflow через **Actions → Deploy invitation to GitHub Pages → Run workflow → main**.

Для локальной проверки именно production-сборки выполните `npm run build`, затем `npm run preview` и откройте напечатанный адрес с путём `/toi-invitation/`. В PowerShell при необходимости используйте `npm.cmd`. GitHub Pages пока не опубликован: push и изменение настроек GitHub не выполнялись.

Официальная инструкция по выбору источника публикации: [GitHub Pages — GitHub Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Проверка

Проверка адреса, ссылки и таймера: запустите локальный сайт, затем `node scripts/check-event-browser.mjs` (по умолчанию адрес `http://127.0.0.1:5175`; при другом порте задайте переменную окружения `PREVIEW_URL`). Проверяются 360/390/430/1440 px, разные часовые пояса, ежесекундное обновление и сообщение «Мерейтой басталды!» на границе начала. Часы браузера подменяются только в проверке. Переход 2ГИС перехватывается локально; реальные ответы в Google Forms не отправляются. В обычной работе после достижения даты интервал останавливается, а при возвращении на вкладку до даты таймер сразу пересчитывается по текущему времени устройства.

Открытие занимает около 2,6 секунды: печать 240 мс, клапан 700 мс, выдвижение письма 850 мс, увеличение и переход 820 мс. Первый запуск всегда ждёт нажатия, включая reduced motion. При reduced motion после нажатия сразу открывается приглашение. Кнопка «Қайта ашу» на первом экране сайта повторяет сцену одним нажатием; заполненная RSVP-форма сохраняется. До окончания сцены основной сайт `inert`, прокрутка заблокирована; затем фокус переносится на заголовок письма. Состояние открытия не записывается в localStorage, поэтому перезагрузка снова показывает закрытый конверт.

Проверьте 360, 390, 430 px и десктоп: раскрытие конверта, переход к письму, фокус клавиатуры, обязательное имя, варианты участия, демонстрационный режим, сетевую ошибку и reduced motion. На iOS/Android используйте настоящий браузер перед рассылкой гостям. Отправка в реальную Google Form проверяется после подключения вашей формы.

Автоматическая браузерная проверка: запустите `npm run dev`, затем в другом терминале `node scripts/check-browser.mjs`. Требуется установленный Microsoft Edge. Скрипт проверяет ширины 360/390/430/1440 px, фокус, форму и reduced motion; снимки сохраняет в игнорируемую папку `test-results/`. Все POST перехватываются локально: проверка не отправляет ответы в Google Forms. Проверка в Edge не заменяет проверку на настоящем iPhone.

Официальные справочники: [Vite — GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [Google — FormResponse.submit](https://developers.google.com/apps-script/reference/forms/form-response).
